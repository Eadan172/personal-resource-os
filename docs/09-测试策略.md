# N. 测试策略

原则：断网 + Mock Provider 下全部测试确定性通过；Acceptance Criteria 不只验证“页面打开”。

## 1. 测试金字塔

| 层 | 工具 | 覆盖 |
|---|---|---|
| Unit | pytest | extraction / retrieval / audit / tasks / pipeline 各模块 |
| Integration | pytest + 临时 SQLite | 闭环链路、migration、backup/restore |
| E2E | 脚本（cli/api 全链路） | Capture→…→Rollback 一次跑通 |
| Contract | pytest（mock connector） | MCP Gateway 工具面、Connector 契约 |
| Security/Permission | pytest | 策略拒绝、密钥不落日志、untrusted 隔离 |

## 2. 专项测试（对应 §十七）

| 专项 | 关键用例 |
|---|---|
| AI Mock 确定性 | MockProvider 同输入恒同输出；CI 无网络全绿 |
| Data-loss prevention | pipeline 任一环节抛异常 → 原始 content 字节级不变；对象仍 inbox |
| Rollback | create/update/delete/restore 四类 op 单条回滚；回滚记录自身入审计 |
| Citation correctness | 每个引用 span 与原文切片完全一致；无证据问题返回拒答且 citations=[] |
| Agent loop/timeout/budget | max_steps/timeout/token/retry 超限即 abort；confirm 动作未批准不落库 |
| Connector contract | mock connector 调用每个 MCP tool；未授权工具被拒；外发分级检查生效 |
| Permission | Agent 写 objects.content 被 schema 层拒绝；越 scope 工具调用被拒 |
| Security | 日志中不出现 api key 子串；出站请求只命中 allowlist 域名 |

## 3. 验收标准（MVP 出口）

1. `make test` 全绿（无网络）。
2. E2E 脚本一次通过，且断言每一步的中间状态。
3. 种子 10 万对象，FTS 检索 P95 < 300ms。
4. 手工演练：注入 Provider 故障 → 数据无损；误删对象 → 回滚恢复。
