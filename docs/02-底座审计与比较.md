# B. 候选底座/项目审计与比较 + M. 安全审计清单

审计日期：2026-09-29。方法：公开仓库元数据、官方文档、CVE/GHSA 记录、第三方评测交叉验证。
声明：本审计不声称任何项目“没有后门/绝对安全”，只给出审计范围、已发现问题、风险等级与剩余不确定性。

### 关键审计发现

1. **没有候选项目适合直接 Fork 当底座。** 符合需求 §十九「不要直接 Fork 大型项目改核心」。AFFiNE 有 CVSS 8.8 的 RCE 前科且架构重；Joplin/Trilium 是 AGPL，修改后作为网络服务分发有源码公开义务；Khoj 云版关停说明其商业模式不稳；Obsidian 本体闭源，只能作宿主不能作核心。
2. **Obsidian 社区插件生态是已知攻击面。** Elastic 2026-04 披露的 REF6598 行动证明：攻击者可通过“共享 vault + 诱导开启插件同步 + 命令执行类插件”完成投递。因此本项目的 Obsidian 插件必须：(a) 自研薄适配层；(b) 禁用/不依赖任何具备 shell 执行能力的第三方插件；(c) vault 内不存放密钥。
3. **MCP 生态已成熟且刚完成重大修订。** 2026-07-28 规范为第五个主版本：核心转为无状态（移除 initialize 握手与 Mcp-Session-Id）、新增 `server/discover`、多轮请求（MRTR，可做审批检查点）、`Mcp-Method`/`Mcp-Name` 路由头（网关可按工具做策略与审计）、Tasks/MCP Apps 扩展框架、OAuth 2.0 强化、12 个月弃用周期；2025 年底起由 Linux Foundation 托管。本项目的 MCP Gateway 直接对齐该版本。
4. **WorkBuddy 开放能力已核实**：腾讯 CodeBuddy 团队 2026-03-09 发布；内置 MCP 协议支持与 20+ 技能包；企业微信接入走官方「智能机器人 API 模式」（管理后台创建机器人，长连接只需 Bot ID + Secret）；可作为微信/企微远程入口与执行通道。
5. **IMA（腾讯 ima）开放能力已核实**：2026-05-28 起 ima 知识库接入 WorkBuddy，知识资源可被外部 Agent 调用；官方曾预告开放 API。当前定位为「外部知识源/导入来源」，不作事实源。

## 2. 结论

- 主路线确认：**Obsidian（薄宿主，专有但免费）+ 自研独立 Agent Core + MCP Gateway**（选择 52-F）。
- 核心领域逻辑零依赖任何候选项目内部代码；仅通过 Obsidian 公开插件 API 与文件系统（Markdown vault）交互。
- Khoj 的「scoped agents + automations + citations」设计、Trilium 的「属性/关系系统」作为实现参考，不引入其代码（避免 AGPL 传染与供应链面）。

## 3. M. 安全审计清单（进入正式构建的每个依赖/插件必过）

### 3.1 项目级
- [ ] LICENSE 全文核对（以仓库 LICENSE 文件为准，不信 GitHub 元数据；AGPL/双许可需法务确认）
- [ ] 最近 6 个月提交/Release 频率；维护者数量；治理模式（厂商/社区/个人）
- [ ] SECURITY.md 存在性与响应承诺；GitHub Security Advisories 历史
- [ ] Issues/PR 中未修复的安全问题
- [ ] CVE/GHSA/OSV 全量扫描（工具可用时跑 CodeQL/Semgrep/OSV-Scanner）

### 3.2 代码级
- [ ] 依赖树与 transitive dependencies 审查（`npm ls --all` / `pipdeptree`）
- [ ] install/postinstall 脚本审查
- [ ] 是否存在 shell / child_process / exec / eval 能力及其调用条件
- [ ] 是否存在不受限文件系统访问
- [ ] 是否读取 secret/token/credential（环境变量、keychain、配置文件）
- [ ] telemetry / analytics（默认开启即拒绝，除非可显式 opt-in 且默认关闭）
- [ ] 实际网络请求域名清单（静态扫描 + 运行时抓包对照）
- [ ] 第三方 binary / prebuilt artifact 的哈希与来源
- [ ] 构建产物与源码一致性（reproducible build 或官方签名）

### 3.3 运行时
- [ ] 运行时网络流量可观测（出站日志 + allowlist）
- [ ] 敏感插件沙盒化/最小权限隔离方案
- [ ] Obsidian 侧：vault 内无密钥；不安装命令执行类社区插件；插件同步设置默认关闭

### 3.4 已知风险等级评定（本轮）

| 对象 | 风险等级 | 说明 |
|---|---|---|
| Obsidian 本体 | 中 | 闭源不可审计；只作宿主，核心数据经自有管道加密落 SQLite |
| Obsidian 社区插件 | 高 | REF6598 已实证攻击链；策略：白名单制，默认不装 |
| AFFiNE 自托管 | 中-高 | RCE 前科 + 组件重；不采用 |
| Joplin/Trilium/Khoj 代码复用 | 中 | AGPL 传染 + 供应链面；仅参考设计 |
| WorkBuddy/ima Connector | 中 | 腾讯官方通道；仍需独立 secret、出站 allowlist、全审计 |
| MCP 生态第三方 Server | 高 | 82% 社区 MCP Server 存在路径穿越类问题（Practical DevSecOps 统计，2026）；第三方 MCP Server 一律视为不可信输入源 |

### 3.5 剩余不确定性
- Obsidian 闭源组件的内部行为不可验证，只能黑盒观测。
- WorkBuddy/ima 的开放 API 仍在演进，Connector 契约需以接入时最新官方文档为准。
- 任何审计只能覆盖当前版本；依赖升级必须重新过清单。
