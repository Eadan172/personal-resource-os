# A. 需求规格化定义（Formal Requirement Specification）

版本：v0.1（第一轮交付）  日期：2026-09-29
来源：用户初步构想 + 52 项已确认产品选择（见 coding prompt §三），本文件只做规格化，不重新发散。

## 1. 产品定位

**Personal Resource OS**：以本地个人数据为唯一事实源（Source of Truth）、由 Agent 持续自动整理、连接、维护并执行的个人资源操作系统。

- 不是笔记软件（Obsidian 只作薄宿主）。
- 不是 RAG 聊天机器人（问答只是 Agent 能力之一）。
- 心智模型：人负责投入资源与关键决策；Agent 负责整理、发现关系、维护任务、阶段总结、执行被授权动作。

## 2. 目标（Goals）与非目标（Non-Goals）

| 编号 | 目标 |
|---|---|
| G1 | 想到什么就记什么：全渠道快速 Capture，统一进 Inbox |
| G2 | AI 自动整理：分类、摘要、实体/任务提取、关系建议，全部可追溯 |
| G3 | 混合检索 + 有证据问答：Keyword + Semantic + Metadata；无证据明确说不知道 |
| G4 | 任务系统：全字段 Task，AI 自动创建，用户可审核 |
| G5 | 阶段总结：日/周/月/自定义区间，输出行动建议并可一键转 Task |
| G6 | 安全：本地优先、离线可运行、密钥安全存储、最小权限、全程审计可回滚 |

| 编号 | 非目标（第一阶段） |
|---|---|
| NG1 | 多人协作 / SaaS 化 |
| NG2 | 内建多设备同步 |
| NG3 | 视频语义理解（第一版只做保存 + 转写 + 摘要 + 提取） |
| NG4 | 自研日历/提醒生态（借用成熟插件/集成） |
| NG5 | 逆向微信协议（只走官方能力） |

## 3. 用户与运行环境

- 单用户个人工具；第一阶段以 Windows 为主；桌面/移动端响应式 UI。
- 完全离线可运行；云端 LLM 是可选项，且外发边界显式可控。
- 部署：Docker + 本地运行，一条命令启动。

## 4. 功能需求（FR）

| 编号 | 需求 | 关键约束 |
|---|---|---|
| FR-01 快速记录 | 文本框、Markdown、全局快捷键 Capture、浏览器入口、剪贴板、文件拖入、手机快捷入口 | 全部统一进 Inbox（FR-02） |
| FR-02 统一 Inbox | 所有新内容默认 lifecycle=inbox，等待 AI 整理 | AI 处理失败不得丢原始数据 |
| FR-03 智能处理 | 自动分类（Note/Idea/Task/Person/Project/Event/Bookmark/Document/Meeting/Conversation/Topic/Concept）、摘要、重点提取 | 保留原文；AI 结果与原文分离存储并互相关联 |
| FR-04 重点提取 | 日期、人物、地点、金额、项目、任务、决策、风险、联系事项 | 每个提取字段必须能回溯到来源文本片段（offset） |
| FR-05 任务管理 | 标题/来源/截止/优先级/状态/项目/人员/标签/创建/完成时间/审计 | AI 自动创建；支持优先级、完成状态、一键转 Task |
| FR-06 关系系统 | related_to/mentions/belongs_to/assigned_to/depends_on/derived_from/contradicts/supports/duplicate_of/references | AI 建关系默认“建议 + 审核”，不自动合并重复 |
| FR-07 混合检索 | FTS + 向量 + 元数据过滤 + 时间过滤 + rerank | 检索结果可跳回原文位置 |
| FR-08 引用问答 | RAG 流程：Intent/Scope → Hybrid Retrieval → Rerank → Evidence → Answer → Citation | 无证据必须回答“不知道”；事实与推断分离 |
| FR-09 阶段总结 | 日/周/月/任意区间：发生了什么、主题、新发现、已完成、未完成、人物、决策、风险、下一步 | 行动建议可一键转 Task；决策评估预留可插拔 Decision Evaluation Model 接口（“Jev模型”待确认，见 ADR-007） |
| FR-10 自定义 Agent | 用户可创建 Agent：name/purpose/instructions/allowed tools/scopes/model/trigger/output schema/approval policy/retry policy | max steps、timeout、token 预算、递归深度、写范围、出站网络范围全部受限 |
| FR-11 自动化 | 事件触发、定时、Inbox 自动处理、周期重建索引、周期总结 | 处理时机可配置：立即/异步/手动/夜间批处理/自定义 |
| FR-12 审计与回滚 | 所有 Agent 写操作有 operation log + diff + rollback；删除默认可恢复 | 不可逆操作必须有保护措施 |
| FR-13 多 Provider | DeepSeek、Qwen、任意 OpenAI-compatible API；Chat/Embedding/Reranker/OCR 可分别配置 | Provider Adapter 架构；密钥走 OS secret store |
| FR-14 多模态资源 | HTML/URL/PDF/Office/文本/MD/图片/视频/音频/笔记/Meeting/剪贴板/拖入文件 | 原始文件必留；衍生数据带 source_id/content_hash/timestamp/processor_version |
| FR-15 外部联动 | MCP Gateway；Connector：WorkBuddy、微信（经 WorkBuddy 官方能力）、IMA | 外部渠道非事实源；Connector 不得绕过 Agent Policy |
| FR-16 UI | Dashboard/Inbox/Search/AI Chat/AI Sidebar/Command Palette/Related/Backlinks/Graph/Task Center/Timeline/Summary/Settings/Approval Center/Audit Log | 移动端重点：Capture/Search/Task/AI；桌面端：工作台/Graph/Agent 管理/Review |
| FR-17 备份恢复 | JSON 导出 + 完整备份/恢复 + DB migration | migration 幂等 |
| FR-18 审批中心 | 敏感操作（删除、外发、批量改写）进入 Approval Queue | 未批准不执行 |

## 5. 非功能需求（NFR）

| 编号 | 需求 |
|---|---|
| NFR-01 隐私 | 本地优先；默认零 telemetry；出站请求有 allowlist，默认最小开放 |
| NFR-02 可信 | 区分原始事实/用户编辑/AI 提取/AI 推断/AI 建议；AI 推断不得伪装成事实 |
| NFR-03 可恢复 | 原始资源永不因 AI 失败丢失；任何 mutation 可审计、可回滚 |
| NFR-04 离线 | 无网络时 Capture/检索/任务/总结（本地模型）可用 |
| NFR-05 可测 | Unit + Integration + E2E + AI Mock 确定性测试 |
| NFR-06 性能（MVP 目标） | 10 万级对象下 FTS 检索 P95 < 300ms；Capture 落库 P95 < 100ms |
| NFR-07 供应链 | 进入正式构建的第三方依赖必须过审计清单（见 02 文档 §M） |

## 6. 验收标准（总体 Acceptance Criteria）

1. 闭环可运行：Capture → Inbox → AI 分类 → 持久化 → 混合检索 → 带引用问答 → 生成任务 → 审计 → 回滚，全链路有自动化测试覆盖。
2. 断网 + Mock Provider 下全部测试通过（确定性）。
3. 任一 AI 处理环节注入失败，原始对象内容字节级不变。
4. 任意 Agent 写操作可在审计日志中找到 before/after，并可单条回滚。
5. 无证据问题返回明确“不知道”，且不含编造引用。
