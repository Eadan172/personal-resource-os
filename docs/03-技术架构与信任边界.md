## 2. 组件职责

| 组件 | 职责 | 不做什么 |
|---|---|---|
| Obsidian 薄插件 | 笔记编辑体验、vault 文件读写、把变更事件推给 Core、展示 Core 的 Related/Backlinks/Summary | 不含领域逻辑、不直连 LLM、不存密钥 |
| Web Dashboard | 综合工作台、Graph、Review/Approval、Audit、Agent 管理 | 不直接读写 SQLite（一律走 Core API） |
| Agent Core | 全部领域逻辑（§四.2 全部能力） | 不绑定任何宿主/渠道/Provider |
| Local Store | SQLite（结构化+FTS5）+ 文件仓库（原始附件/导出）+ migrations + backup | 永不因 AI 失败丢数据 |
| MCP Gateway | 对齐 MCP 2026-07-28 无状态规范；工具注册、策略执行、审批检查点（MRTR）、审计 | 不绕过 Agent Policy；不做业务逻辑 |
| Provider Adapter | Chat/Embedding/Reranker/OCR 四类能力分别配置；DeepSeek/Qwen/OpenAI-compat/本地 | 密钥不落库、不进日志、不进模型上下文 |

## 3. 技术选型（详见 ADR-002）

- **Core：Python 3.12 + FastAPI + SQLite(FTS5)**。理由：AI/Agent 生态最成熟、stdlib 覆盖 MVP 闭环（sqlite3/hashlib/json/urllib）、Docker/Windows 友好、测试确定性强。
- **Obsidian 插件：TypeScript**（官方插件 API 唯一选项）。
- **Web Dashboard（V1）：React + Vite**（复用 webapp 生态）；MVP 阶段先以 CLI + 极简 Web 页面验证闭环。
- **向量**：MVP 阶段 FTS5 为主；Embedding 接口预留（本地 bge/m3e 或云端），V1 接入 RRF 融合。

## 4. D. Trust Boundary（信任边界）

```
边界 TB-1 [设备内/进程间]  宿主(UI 层) ⇄ Core API
  - 仅监听 127.0.0.1；本地 token 鉴权；UI 不可信输入全部校验
边界 TB-2 [Core/存储]     Core ⇄ SQLite + 文件仓库
  - 只有 Core 可写；删除=软删除；所有 mutation 进 audit_log
边界 TB-3 [Core/LLM]      Core ⇄ Provider Adapter ⇄ 云端/本地模型
  - 出站 allowlist（默认仅配置的 provider base_url）
  - 外发内容显式标记（数据分类：public/internal/private），private 默认禁外发
  - API Key 存 OS secret store（Windows Credential Manager / keyring），不进 DB/日志/prompt
边界 TB-4 [Core/外部渠道]  MCP Gateway ⇄ WorkBuddy/企微/ima
  - 每个 Connector 独立 secret + 独立权限范围；默认拒绝高风险外发
  - 外部输入一律视为不可信内容（防提示注入）：进 Inbox 标记 untrusted，不参与系统提示
边界 TB-5 [Core/插件生态]  Obsidian 社区插件 / 第三方 MCP Server
  - 白名单制；第三方 MCP Server 输出视为不可信数据
边界 TB-6 [备份]          backup/restore
  - 备份文件加密可选；restore 前校验 migration 版本与完整性哈希
```

### 数据分级与外发策略（选择 3-C）

| 级别 | 定义 | 云端 LLM | 外部渠道 |
|---|---|---|---|
| public | 用户显式标记可外发 | 允许 | 允许 |
| internal（默认） | 普通笔记/任务 | 仅用户选择该条/该范围时允许 | 需审批 |
| private | 密钥、证件、财务等（规则+用户标记） | 禁止 | 禁止 |

## 5. 部署形态

- `docker compose up` 一条命令：core 服务 + 数据卷；Obsidian 插件指向 `http://127.0.0.1:8765`。
- 完全离线模式：`PROVIDER=mock|local`（Ollama），所有测试在 Mock Provider 下确定性运行。
- 标准命令：`make dev / test / lint / typecheck / build / e2e / backup / restore`。
